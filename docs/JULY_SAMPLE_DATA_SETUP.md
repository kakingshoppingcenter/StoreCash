# July 2026 Performance Test Data

StoreCash includes an administrator-only generator for a complete temporary July 2026 test cycle.

## What it creates

For every active branch, the generator creates one Daily Store Entry for every date from July 1 through July 31, 2026.

With seven active branches, this produces 217 reports.

The data includes:

- CASH, G-CASH, MAYA, CREDIT, DEBIT, CHEQUE, SALMON, and OTHER values
- Realistic customer counts
- Higher weekend values
- Approximately 20% pending verification records
- Matched deposit verifications
- Controlled shortages and overages requiring remarks
- Audit records generated by the normal report and verification triggers
- Store remarks beginning with `[SAMPLE DATA JULY 2026]`

The generated values are deterministic, making repeated testing consistent after a full reset.

## Safety rules

- Only an active System Administrator can preview or generate the data.
- The server requires the exact phrase `GENERATE JULY 2026 SAMPLE DATA`.
- Generation is refused if any July 2026 report already exists.
- Existing reports are never overwritten or updated.
- The generator is locked to July 1-31, 2026.
- The server-only database function is executable only by `service_role`.
- The browser does not receive a privileged Supabase key.

## Required deployment

1. Back up the Supabase database.
2. Run `supabase/sample_data_extension.sql` in Supabase Dashboard > SQL Editor.
3. Deploy `supabase/functions/admin-sample-data/index.ts` using the exact Edge Function name `admin-sample-data`.
4. Keep Verify JWT disabled for this function because the function validates the caller token and administrator profile internally.
5. Refresh the GitHub Pages application and sign in as a System Administrator.

## Generate the test month

1. Open Administration.
2. Find **July 2026 Performance Test Data** above **Data Reset and Recovery**.
3. Review the active branch, expected report, and existing July report counts.
4. Select **Generate July Sample Data**.
5. Type `GENERATE JULY 2026 SAMPLE DATA` exactly.
6. Confirm that the records are temporary test data.
7. Generate the records.

After generation, the reporting controls switch to the July 1-31 date range when the range controller is available.

## Recommended tests

- Open Dashboard using Day, Week, and Date Range modes.
- Compare totals when switching between July dates.
- Review matched, pending, shortage, and overage cases.
- Test Branch Reconciliation and Payment Channel Mix.
- Test a restricted Deposit Checker account.
- Test the Credit/Debit auto-account option.
- Test Branch Reports and Executive Summary.
- Export the July range to XLSX and open it in Microsoft Excel.
- Test phone, tablet, laptop, and large-monitor layouts.
- Observe load time, scrolling, silent refresh, and browser memory use.
- Confirm permissions hide unauthorized modules and branches.

## Remove the test data

Use **Administration > Data Reset and Recovery** after completing the test.

The reset removes:

- Daily reports
- Deposit verifications
- Test audit records

The reset preserves:

- Authentication accounts
- Profiles
- Branches
- Roles
- Permissions
- Database structure and security policies

The reset is system-wide, not July-only. Do not run it after real operational records have been entered unless management has authorized a complete operational reset and a verified backup exists.
